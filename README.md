# CounterSync — синхронизация потоков через lock

Практическое задание по системному программированию (МДК.01.04).
Демонстрация проблемы гонки (race condition) при работе нескольких потоков с общим счётчиком и её решения с помощью критической секции lock в C#/.NET.

## Задание

Несколько потоков увеличивают общий счётчик:
- показать неправильный вариант — без синхронизации;
- показать правильный вариант — с lock.

Никаких ручных правок кода не требуется.

## Параметры эксперимента

| Параметр | Значение |
|---|---|
| Потоков | 8 |
| Инкрементов на поток | 1 000 000 |
| Ожидаемое значение | 8 000 000 |

## Пример вывода программы

```
=== Демонстрация синхронизации потоков (lock) ===
Потоков:              8
Инкрементов на поток: 1 000 000
Ожидаемое значение:   8 000 000
------------------------------------------------------------
Время без lock: 90 мс
[Без lock] Результат:       1 306 410  ПОТЕРЯ ДАННЫХ!

Время с lock:   1563 мс
[С lock]   Результат:       8 000 000  OK
------------------------------------------------------------
Вывод: без lock часть инкрементов теряется из-за гонки,
      с lock счётчик всегда равен ожидаемому значению.
```

Точное значение без lock при каждом запуске разное — это и есть проявление гонки. Значение с lock стабильно равно 8 000 000.

## Как работает программа

Программа запускает 8 потоков, и каждый поток должен 1 000 000 раз прибавить единицу к общему счётчику counter. Если бы всё работало идеально, в конце мы получили бы 8 000 000.

Проблема в том, что потоки работают одновременно. Два потока одновременно прочитали число 100, оба прибавили 1, оба записали 101. Итог: было 100, стало 101 — хотя должно было стать 102. Так происходит при неверном варианте.

### Неверный вариант (без lock)

Все потоки увеличивают один и тот же счётчик командой counter++, но эта команда не мгновенная. На уровне процессора она состоит из трёх шагов:

1. Прочитать текущее значение счётчика из памяти
2. Прибавить к нему 1
3. Записать результат обратно в память

Чем больше потоков и итераций — тем больше потерь. Поэтому итоговое число всегда меньше 8 000 000 и каждый раз разное — это и есть гонка.

### Правильный вариант (с lock)

Мы оборачиваем counter++ в блок lock:

```
lock (locker)
{
    counter++;
}
```

lock — это критическая секция: пока один поток находится внутри неё, все остальные потоки ждут своей очереди у входа. Получается, что шаги прочитать, прибавить, записать всегда выполняются целиком одним потоком, никто не может влезть в середину и испортить результат.

Итог: все 8 000 000 инкрементов учитываются, и счётчик стабильно показывает 8 000 000, но сама команда выполняется дольше.
